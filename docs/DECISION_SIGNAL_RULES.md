# 决策信号行为准则

本准则约束 Lina 的硬条件与方向信号抽取、评分、评测和发布。违反任一条时，不得默认启用自动综合排序。

## 抽取

1. 只从输入文档的直接证据生成事实，不使用常识补全候选人信息。
2. 候选人侧缺少事实时返回 `unknown`；不得编码为兼容、失败或零分。
3. 范围表达统一为可比较下界：年换算为 12 个月，岗位区间取最低承诺值。
4. 省略“实习”的时长短语只在“连续”或“至少”等承诺词存在时识别，避免把历史经历时长当作未来承诺。
5. 方向判断必须有候选人目标或偏好证据；普通技能出现不能替代方向偏好。

## 证据

1. 每个状态必须保存 JD 证据；`met` 和 `unmet` 还必须保存候选人证据。
2. 证据 offset 必须能从原文精确还原。
3. 只返回完成判断所需的最小充分证据，不附带未参与比较的历史事实。
4. 解释必须区分自动抽取、人工确认和 Gold 标签来源。

## Gold 与评测

1. Gold 在实现变更前冻结；只能因标注越界或证据错误修订，并记录原因。
2. 同一岗位同一硬条件只能有一个逐项标签。
3. 自动评测必须直接运行抽取器，不得把岗位级 Gold 分数注入自动路径。
4. 同时报告逐项状态准确率、证据 Precision/Recall/有效率、逐项已知率和排序指标。
5. 岗位级信号覆盖率不能替代逐项已知率；识别出更多 `unknown` 可能是质量提升。
6. Top-1 不能单独作为发布依据，必须同时报告 Pairwise Accuracy。
7. 用户声明同优先级的岗位必须使用并列组；Pairwise 和逆序对跳过组内顺序，Top-1 接受并列首组任一岗位。
8. 排序误差分析必须报告逐岗技能、硬条件、方向和总分分量。
9. 方向偏好强度必须来自用户确认；`0.0` 是有效值而不是未知，且不得伪造成文档证据。
10. 岗位命中多个方向时使用公开、确定性的聚合规则；类别拆分必须对应真实决策差异。
11. Agent、API、CLI 必须消费同一确认模型；入口测试既要证明值生效，也要覆盖禁用和越界拒绝。
12. 多 Gold 稳定性必须同时报告 taxonomy 覆盖、数据集/岗位规模、宏平均和最差集；职位摘要不得充当完整证据 Gold。
13. MAE 必须与信号 coverage 联合解读；unknown 被排除后得到的低 MAE 不能证明召回完整。
14. 任一明确 hard `unmet` 必须作为排序 veto；多地点按集合匹配，优先语气按所在子句判断，unknown 仍不得视为失败。
15. 可由 required 技能缺口解释的逆序应转化为可验收证据计划，不通过调权重隐藏；计划目标必须通过 Reviewer 的 gap 白名单。
16. 性能技能证据必须冻结环境、输入、warmup、同步和迭代口径，并同时报告延迟、吞吐、内存与跨设备误差。
17. C++/CUDA 优化必须保留 Python reference 与误差阈值；首轮负结果不得隐藏，只做有明确瓶颈假设的有限优化。
18. 无 NVIDIA runtime/NVCC 时不得宣称 CUDA 已验收；条件 skip 必须说明原因，并由真实 GPU artifact 关闭验证缺口。

## 发布

1. 自动综合排序默认关闭，直到冻结数据上逐项与排序指标达到预先定义的阈值。
2. 新表达必须有正例、反例和私有 Gold 回归，优先保证 Precision。
3. 私有简历、JD、Gold 和报告不得进入 Git；公开文档只记录匿名聚合指标。
4. 缺用户事实时应请求确认，不应继续扩大解析规则或调整权重掩盖缺口。
