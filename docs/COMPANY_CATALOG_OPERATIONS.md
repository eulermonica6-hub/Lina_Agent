# 公司清单健康与自动轮换计划

> 最近实测：2026-09-30
> 当前清单：46 家
> 原则：自动监控和生成变更建议，人工审核后才修改正式清单

## 1. 当前入口健康

运行 `lina-monitor` 对 46 个官方招聘入口执行真实网络探针。本次结果为 `partial`：

| 状态 | 数量 | 公司 | 含义 |
| --- | ---: | --- | --- |
| 可达、待职位解析器 | 42 | 除下列 4 家外的全部公司 | HTTP 页面可访问，但尚未证明已抓取职位列表 |
| 自动探针被阻止 | 3 | TSMC、SpaceX、Tesla | HTTP 403；官方入口存在，但当前自动访问受 WAF/反爬限制 |
| 网络错误 | 1 | 中芯国际 | TLS 连接异常，需人工复核或替换稳定官方入口 |

TSMC 曾通过浏览器内容抓取显示职位列表，因此属于人工可访问、自动探针受限。SpaceX、Tesla 和中芯国际不能在本次检查中证明自动可访问。

报告生成命令：

```bash
uv run --locked lina-monitor --output artifacts/weekly-monitor.json
```

“入口可达”不等于“岗位已采集”。只有职位列表解析器返回结构化 `JobLead`，并通过岗位详情复核后，岗位才能进入 live 推荐。

## 2. 两种轮换

### 2.1 每日岗位推荐轮换

当前已经实现。首页在 live 候选集中按当天日期稳定轮换 6 条岗位：

- 国内大厂 2 条；
- 国外大厂 2 条；
- 探索型公司 2 条；
- 某类不足时由其他高分 live 岗位补位；
- 用户偏好、近期点击、地点和岗位类型继续影响排序。

该轮换只改变岗位展示顺序，不自动修改公司清单。

### 2.2 公司成员轮换

计划采用“自动建议、人工批准”的 GitOps 流程，不让定时任务直接改生产清单。

1. **每周健康检查**：记录 HTTP 状态、最终 URL、响应时间、页面指纹和连续失败次数。
2. **每月候选生成**：读取市值榜、用户提名和新出现的相关岗位，生成候选公司报告。
3. **准入检查**：要求官方招聘入口、明确地区、AI/Agent/数据/搜索/基础设施相关性和纳入理由。
4. **变更提案**：机器人创建包含 TOML diff、证据链接和影响说明的 Pull Request。
5. **人工审批**：用户确认新增、换池、暂停或移除后才合并。
6. **合并后验证**：执行目录、监控、推荐、打包和完整回归测试。

## 3. 生命周期状态

未来为公司增加以下内部状态：

| 状态 | 条件 | 行为 |
| --- | --- | --- |
| `candidate` | 市值榜、用户提名或新岗位发现 | 只进入审核报告 |
| `active` | 官方入口可核验，且满足准入标准 | 参加监控和岗位召回 |
| `degraded` | 连续 2 次探针失败或结构变化 | 保留公司，降低采集置信度并告警 |
| `paused` | 连续 4 周失败，且无可用替代入口 | 暂停自动抓取，不进入新推荐 |
| `retired` | 公司关闭招聘、入口永久迁移或方向不再相关，且人工批准 | 从正式目录移除并保留审计记录 |

单次 403、429、超时或 TLS 错误不会自动移除公司。

## 4. 月度轮换评分

公司轮换建议按以下因素生成，不直接作为岗位匹配分：

- 30%：近期 live 且相关的岗位数量；
- 25%：岗位新鲜度与更新频率；
- 20%：招聘入口和解析器健康度；
- 15%：与用户地点、岗位类型和方向偏好的覆盖；
- 10%：市值榜、技术战略或用户明确关注。

大厂池按国内和国外分别维护覆盖；探索池更关注技术集中度、远程/上海可达性和岗位质量。市值变化只触发审核建议，不自动覆盖岗位证据。
