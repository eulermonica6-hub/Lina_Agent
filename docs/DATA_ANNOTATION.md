# Lina 数据匿名化与标注指南

本文定义真实 JD 和简历如何转化为可复现评测数据。目标不是“让模型看过一些例子”，而是建立独立于实现的期望答案，用于判断规则、模型或工作流是否真的改善。

## 1. 为什么需要标注

程序只能输出预测，无法自己证明预测正确。人工标注提供一份固定的参考答案，也称 Gold Label。

没有标注时只能说“结果看起来合理”；有标注后才能计算：

- Precision：提取出的字段有多少是正确的；
- Recall：JD 中应提取的字段有多少被找到；
- Exact Match：整条 JD 的全部硬条件是否一致；
- 证据有效性：引用片段是否真的支持字段；
- 回归：修改规则、Prompt 或模型后是否破坏旧案例。

标注不是把模型答案抄一遍，而是在运行被测实现之前，按统一规则独立写出期望结果。

## 2. AI 与人工如何分工

AI 可以完成第一轮：

1. 去除或泛化敏感信息；
2. 提取候选标签和精确原文片段；
3. 标出“硬性要求、偏好、歧义、未声明”；
4. 检查 JSON Schema、证据子串和重复案例；
5. 生成待复核问题。

人工仍需做最终确认，因为“优先”“熟悉”“有经验者”“优秀者可放宽”等表达是否构成硬门槛，会直接影响岗位筛选。对于 10 条小型数据集，推荐 AI 初标全部案例，用户复核全部硬条件与歧义项。确认后的数据才称为 Gold Label。

## 3. JD 匿名化

原始 Boss JD 只保存在 `data/private/jd_raw/`，不得提交 Git。匿名副本先放在 `data/private/jd_anonymized/` 复核。

处理规则：

- 公司、团队、联系人和招聘者替换为稳定占位符，例如“公司 A”“团队 A”；
- 删除电话、邮箱、微信、详细办公地址和追踪参数；
- 删除能反推出个人身份的内部项目名或联系人描述；
- 保留岗位语义所需的城市、学历、毕业年份、经验、技能和职责；
- 保留原句措辞，避免匿名化改变“必须”与“优先”的语义；
- 记录采集日期和私有来源映射，但公开 Fixture 不保存可追踪个人的 URL 参数；
- 不将完整第三方 JD 正文提交到公开仓库；公开评测只保留必要短片段、结构化标签或获得许可的内容。

若 Boss 要求登录、验证码或限制自动访问，不绕过限制。使用用户正常浏览后导出的文本，或由用户共享已登录页面进行人工辅助采集。

## 4. 当前 JD 标签

每个案例对应 `JobParserEvaluationCase`：

```json
{
  "case_id": "real-ai-role-01",
  "description": "匿名化后的必要短片段",
  "expected": {
    "graduation_years": [2027],
    "minimum_education": "bachelor",
    "minimum_years_of_experience": 2,
    "locations": ["上海"]
  },
  "expected_evidence": [
    "2027 届",
    "本科及以上学历",
    "2 年以上工作经验",
    "工作地点：上海"
  ]
}
```

标签规则：

- `graduation_years`：只标明确允许的毕业年份；“应届优先”不标硬条件；
- `minimum_education`：只标最低硬性学历；“硕士优先”不标硕士门槛；
- `minimum_years_of_experience`：只标明确最低年限；“有经验者优先”记为未声明；
- `locations`：标明确工作地点，不根据公司总部推断；
- `expected_evidence`：必须是 `description` 中逐字存在、足以支持标签的最小片段；
- 未声明字段使用空集合或 `null`，不得根据常识补全。

技能、职责、加分项和语义匹配标签将在结构化模型节点实施前单独扩展，不能混入当前硬条件指标。

## 5. 简历匿名化与标注

原始简历放在 `data/private/resume_raw/`。匿名化时删除或泛化：

- 姓名、照片、性别、年龄、电话、邮箱和个人主页；
- 学校、公司、客户、导师和内部系统名称；
- 精确家庭地址、证件、账号和其他身份标识。

保留与岗位判断有关的事实：学历层级、毕业年份、城市偏好、经验时长、技能、职责、项目产出和可验证指标。泛化不能把“参与”改成“负责”，不能新增技术、数字或成果。

简历标注的后续 Schema 至少包含：字段值、证据文本、页码或段落、字符偏移、事实类型和人工确认状态。当前仓库的 `tests/fixtures/resume_anonymized.md` 只是一份匿名演示 Fixture，还不是完成标注的简历 Gold Set。

## 6. 实际操作流程

1. 用户通过正常浏览保存 10 条 JD 原文，并提供原始简历文件。
2. 文件进入 `data/private/`，先检查 Git 忽略状态。
3. AI 生成匿名副本、候选标签和歧义问题。
4. 用户对照原文确认每个硬条件是“必须、偏好、歧义或未声明”。
5. AI 根据确认结果生成评测 JSON，并验证每条证据都是原文子串。
6. 运行当前解析器，记录 TP、FP、FN 和失败案例。
7. 只从失败案例增加规则或模型能力，不为了提高分数改动 Gold Label。
8. 匿名与授权复核通过后，才决定哪些必要短片段可进入版本控制。

## 7. 十条 JD 的复核表

每条 JD 用同一张表确认：

| 项目 | 需要确认的问题 |
| --- | --- |
| 岗位范围 | 是否属于 AI Agent、LLM、RAG、评测、搜索或相关工程岗位 |
| 毕业年份 | 是硬门槛、偏好还是没有声明 |
| 学历 | 最低要求是什么，是否只是“优先” |
| 经验 | 是否明确给出最低年限 |
| 地点 | 工作地点是否明确，是否存在多地点或远程 |
| 证据 | 每个标签由哪段原文直接支持 |
| 歧义 | 哪些内容需要保守留空而不是推断 |
| 隐私与授权 | 是否已去除个人信息，正文是否适合进入公开 Fixture |

对这批数据，AI 可以完成匿名化和初标；人工工作主要是核准高影响语义。预计每条复核 2-5 分钟，10 条约需 30-45 分钟。
