# 迭代 044：岗位 Feed 与对话预览

> 日期：2026-09-28
> 阶段：主动求职产品首个网页切片
> 状态：历史岗位 Feed、简历初筛和类型化对话预览已完成

## 1. 用户问题

0.2.25 首屏仍以手工画像和单个 JD 表单为中心。用户进入 Lina 后看不到岗位机会，也没有自然语言入口；即使文件 Agent 已可用，仍需用户先自行准备 JD 目录。

## 2. 本轮实现

- 首页自动请求 `GET /opportunities`，展示 7 条来自官方页面人工核验记录的 AI/Agent 相关岗位；
- 每条岗位显示公司、标题、地点、方向、摘要标签、核验日期和官方链接；
- Feed 明确标记为 `historical_snapshot`，页面显示“历史核验快照”，不声称实时招聘；
- 文件 Agent 默认将当前 Feed 转为 Markdown 岗位目录，用户只上传简历即可初筛；
- 保留“自带 JD 目录”模式，兼容原有完整文件 Agent；
- 右下角新增 Lina 对话按钮和面板；
- `POST /assistant/messages` 提供类型化预览，可导航岗位 Feed 和简历上传入口。

## 3. 数据边界

Feed 数据来自 2026-09-14 的官方岗位人工核验记录，不在页面加载时访问招聘网站。所有岗位均标记 `needs_reverification`，申请前必须打开官方链接确认是否仍开放。

Feed 转换出的 JD 目录只包含当前公开摘要标签，不等同于完整 JD。简历结果是初筛，不应替代打开官网阅读职责、资格和隐私声明。

## 4. 对话边界

当前对话不是通用 LLM 会话，也没有长期记忆或联网工具。它只识别岗位查找、简历上传等少量意图并触发已注册页面动作。默认回复明确说明“尚未联网自主搜索”。

后续对话层必须调用类型化搜索、比较、订阅和投递草稿工具，不能在 Prompt 中复制业务规则或绕过用户审批。

## 5. 测试与视觉验收

新增 API 与 Playwright 场景覆盖：

1. Feed 日期、官方 URL、公司覆盖和非实时状态；
2. 岗位与简历意图路由，以及默认能力边界；
3. 首页自动渲染岗位卡；
4. 对话打开、聚焦、发送、建议动作和关闭；
5. 只上传简历即可生成 Feed 岗位目录并调用文件 Agent。

完整 Web 套件共 20 项。桌面三列岗位卡、移动单列、对话浮层和关闭状态均完成视觉验收；移动端无横向溢出。

## 6. 下一步

用统一 `JobSourceAdapter` 替换静态快照来源，先接一个条款允许的真实官方招聘源。默认测试继续使用 Fixture，真实网络探针独立运行，并保留来源失败、抓取时间和 `needs_reverification` 状态。

## 7. 行为准则

- 自动展示不等于实时获取，必须展示数据时间和来源状态；
- 历史岗位不能使用“招聘中”措辞，除非本次访问已验证；
- 摘要匹配不能包装成完整 JD 匹配；
- 对话 UI 上线不代表已具备通用对话 Agent；
- 新入口必须保留已有文件 Agent 和结构化工具的兼容路径。
