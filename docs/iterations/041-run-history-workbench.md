# 迭代 041：Run 历史与 Diff 工作台

> 日期：2026-09-28
> 阶段：Phase 3A.5 历史审计界面
> 状态：只读历史与结构化 Diff 已完成

## 1. 目标

把已发布的 Agent Run Snapshot 与 Diff API 接入工作台，使用户无需读取 JSON 就能查看最近运行并比较版本变化。当前工作台仍不上传文件 Agent 输入，本轮只做只读历史审计，不混入新的运行创建流程。

## 2. 交互

- 用户点击“刷新历史”后请求最近 20 条 Snapshot；
- 默认选择次新 Run 为基线、最新 Run 为目标；
- 同一 Run 不能与自身比较；
- 运行列表展示时间、状态、岗位数、结果数、gap 数和短 run ID；
- Diff 展示：
  - 候选文档、岗位目录、确认事实和行动计划是否变化；
  - 岗位排名位移，以及新增、移除、替换岗位；
  - 总分变化；
  - 新增和已解决 gap。

## 3. 隐私边界

界面只消费脱敏 Snapshot 与 `AgentRunDiff`。不请求 DocumentReference 详情、确认事实详情、原始文档、evidence text、offset 或文件名。Playwright 使用 sentinel 断言页面不出现私密文本。

## 4. 状态与竞态

历史刷新和 Diff 请求各有独立 revision：

- 新刷新使旧历史响应失效；
- 重新选择版本使旧 Diff 响应失效；
- 失败后按钮恢复，状态栏显示 API detail；
- 空历史显示明确空状态，比较按钮禁用；
- 历史状态不受“开始新一轮”表单重置影响。

## 5. 视觉与响应式

- 历史区域使用全宽分隔带，不在卡片中嵌套卡片；
- 桌面端两个选择器横向排列，Diff 使用三列；
- 移动端选择器纵向堆叠，Diff 三列转为单列；
- `scroll-margin-top` 避免 sticky topbar 遮挡历史与 Diff 标题；
- 实测窄视口 `body.scrollWidth == viewportWidth`，无横向溢出。

## 6. 验证

新增 4 个 Playwright 场景：

1. 加载两条历史、默认选择基线/目标并渲染 Diff；
2. 空历史；
3. 历史加载失败与按钮恢复；
4. Diff 请求失败与按钮恢复。

全 Web 套件共 12 项通过，桌面/移动截图人工验收通过。

## 7. 失败与修复

1. 首轮测试在 UI 尚不存在时超时，证明验收锚点准确。
2. 桌面 `scrollIntoView` 后 sticky topbar 遮挡“运行历史”标题。为历史和 Diff 区域增加 `scroll-margin-top`。
3. 两个异步读请求若不分开管理，历史刷新可能误取消 Diff 或旧 Diff 覆盖新选择。使用独立 revision，而不是复用表单 revision。

## 8. 知识与行为准则

- 历史浏览与新 Run 创建是不同工作流，入口和状态应解耦。
- 前端只能显示后端脱敏契约提供的字段，不能通过额外请求拼回敏感信息。
- 版本比较 UI 必须明确基线与目标，不能让 delta 方向依赖用户猜测。
- 只读异步界面同样需要过期响应保护和失败恢复。
- sticky navigation 下的可滚动目标必须设置 scroll margin。
- 空状态、单条历史和同 Run 选择都必须禁用无意义比较。

## 9. 下一步

将文件 Agent 运行入口接入工作台：本地选择简历/JD 文件、显式启用自动信号/LLM、运行后自动刷新历史；上传前展示隐私和确认边界，不把服务端路径暴露给浏览器。

## 10. 面试表达

我把版本化 Snapshot 和 Diff 接入为独立只读历史面板，默认比较次新与最新 Run，并用结构化视图展示输入、确认、排名、分数和 gap 变化。前端不请求原文接口，异步刷新和比较分别做 revision 防护；移动端无横向溢出，Playwright 覆盖成功、空状态和失败恢复。
