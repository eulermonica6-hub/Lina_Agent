# 迭代 022：自动决策信号基线

> 日期：2026-09-14
> 阶段：Phase 2B.2 证据化信号抽取
> 状态：确定性 MVP 完成，保持显式 opt-in

## 1. 目标

把迭代 021 的人工 `DecisionSignals` 接口接到匿名简历和 JD，同时保持三条边界：每个结论必须有原文坐标；候选信息缺失时返回 `unknown`；自动结果必须与人工 oracle 分开评测。

## 2. 实现

- 自动提取毕业届次、学历、地点、每周到岗天数和持续月份。
- 每项硬条件返回 `met`、`unmet` 或 `unknown`，以及候选人/JD 双侧证据。
- 使用方向词表识别 Agent/大模型应用、AI Infra、机器学习和风控方向。
- 候选人没有方向声明时不生成方向分；存在明确方向后才判定岗位方向匹配或不匹配。
- 文件 Agent、CLI 和 API 新增显式自动信号开关，默认排序不变。
- 评测 CLI 新增 `--auto-signals`，独立报告覆盖率、MAE 与 Top-K 指标。

## 3. 私有 Gold 基线

| 指标 | 结果 |
| --- | ---: |
| 硬条件信号覆盖率 | `0.60` |
| 硬条件 MAE | `0.25` |
| 方向信号覆盖率 | `1.00` |
| 方向信号 MAE | `0.28` |
| 未知硬条件项 | `5` |
| Top-1 Accuracy | `1.00` |
| Pairwise Accuracy | `0.70` |

预测排序为 `1 > 4 > 2 > 5 > 3`，人工排序为 `1 > 2 > 3 > 4 > 5`。自动 Pairwise 从 skill-only 的 `0.30` 提升到 `0.70`，但仍低于人工 oracle 的 `1.00`。数据集只有 5 个岗位，这些数字只用于回归和误差定位。

## 4. 学习笔记

1. `unknown` 既不能算兼容，也不能算失败；它必须从分母移除并进入人工确认队列。
2. 方向不匹配需要候选人偏好证据。简历没有方向声明时，不能仅因 JD 出现方向词就打零分。
3. 证据 offset 应从解析后的全局证据行继续切片，不能在岗位局部正文上重新从零计数。
4. 自动抽取评测必须直接运行抽取器；把 Gold 分数注入评分函数只能测 oracle 上限。
5. Top-1 满分与 Pairwise `0.70` 可以同时出现，因此不能只汇报第一名命中。
