# 迭代 060：岗位变化 Inbox

> 日期：2026-09-30
> 版本：0.2.42
> 状态：事件 API、用户状态和独立网页已完成

## 1. 用户确认

- Inbox 使用独立 `/inbox` 页面，首页只增加“岗位动态”和未处理数量，避免重新变拥挤；
- 收藏与待比较可以并存；忽略只影响默认展示，不删除其他标记或审计事件。

## 2. 实现

- 新增 `JobInboxState`，将用户操作与不可变变化事件分离；
- 新增 `JobInboxService`，支持事件类型和处理状态筛选；
- 新增 `GET /inbox/events` 与 `PATCH /inbox/events/{event_id}`；
- SQLite schema 升级到 v5，持久化收藏、忽略和待比较状态；
- 新增独立 `/inbox` 页面，默认展示未处理事件；
- 页面支持 `new / updated / closed / reopened` 和状态筛选；
- 首页顶部显示未处理数量，不把事件列表塞回首页；
- API 响应不暴露内容指纹、内部公司池、原始 HTML 或批次内部字段。

## 3. 验收

- 默认按时间倒序展示未处理事件；
- 读取 Inbox 没有状态副作用；
- 收藏后从未处理视图移除，并可在已收藏视图找到；
- 收藏和待比较可并存，忽略不会清除两者；
- 空更新返回 422，未知事件返回 404；
- SQLite 应用重启后恢复用户状态；
- 桌面和移动端 Playwright 通过，移动端无横向溢出；
- 首页只新增入口和数字，不增加事件卡片。

## 4. 下一步

立即进入自然语言工具对话第一阶段：

1. 将岗位搜索、Inbox 查询和岗位比较注册为类型化工具；
2. 识别“找岗位、筛选岗位、查看动态、比较岗位”意图；
3. 缺少地点、岗位类型或目标方向时主动追问；
4. 所有工具结果保留来源和状态，不让模型把 `unknown` 编造成事实。

后续第二阶段再持久化多轮会话、摘要和恢复点。
