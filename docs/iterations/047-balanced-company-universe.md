# 迭代 047：主池与专注型 AI 公司宇宙

> 日期：2026-09-28
> 阶段：岗位发现范围扩展
> 状态：21 家公司双池目录、混排和网页公司雷达已完成

## 1. 用户问题

只展示知名大厂会产生发现偏差：用户看不到岗位方向更集中、团队更小、远程机会更多的 AI 基础设施和开发者工具公司。简单把更多公司塞进列表也会让大厂凭岗位数量淹没探索机会。

## 2. 双池策略

公司目录分为：

- `anchor`：平台型大厂与稳定主池，提供成熟业务、完整岗位体系和品牌信号；
- `focused_ai`：专注型 AI/开发者工具探索池，强调 Agent、推理、检索、评测、模型平台和远程机会。

`JobLead` 新增 `company_pool`。发现服务分别保持两池内部顺序，再按 anchor/focused_ai 交替输出；全局 limit 在去重和混排后执行。这样探索岗位不会因大厂数量更多而消失。

## 3. 当前公司宇宙

### 主池（10）

腾讯、字节跳动、阿里巴巴、蚂蚁集团、Microsoft、Amazon、Meltwater、小红书、Apple、NVIDIA。

### 专注型 AI 探索池（11）

MiniMax、Baseten、Cohere、Fireworks AI、Anyscale、LlamaIndex、Pinecone、Weaviate、ElevenLabs、LangChain、Together AI。

探索池只纳入本轮能够从官方 Careers 页面确认的公司。未将失效的 Mistral Ashby URL或需要登录的 Hugging Face Jobs 页面纳入正式清单。

## 4. 选择标准

每家公司必须具备：

1. 官方 Careers URL；
2. 与 Lina 用户相关的 AI/Agent/基础设施方向标签；
3. 地区或远程范围；
4. 一句可审查的关注理由；
5. 可进入每周来源健康监控的公开入口。

“小而美”不是融资轮次或估值断言。Lina 使用“专注型 AI”这一可观察分类，避免把未经核验的独角兽状态当作事实。

## 5. API 与网页

`GET /companies` 返回完整目录，`?pool=anchor` 或 `?pool=focused_ai` 可按池筛选。每个对象包含公司、官方 URL、关键词、地区、池和关注理由。

首页新增“公司雷达”：

- 左栏展示主池；
- 右栏展示专注型 AI 探索池；
- 每家公司显示官方链接、地区、关注理由和方向标签；
- 监控横幅显示 21 个来源、10 家主池、11 家探索池。

## 6. 每周监控

每周监控统一使用同一目录，不维护第二份公司名单。首次 21 源真实运行结果：

- 20 个入口：`partial/listing_parser_pending`；
- 小红书：本次 `failed/network_error`；
- 整体：`partial`；
- 失败未阻断其余来源，也未被解释成零岗位。

## 7. 验证

新增测试覆盖：

- 10/11 双池数量和探索池公司集合；
- 所有公司必须有地区与关注理由；
- `/companies` 按池筛选；
- 不同池岗位交替混排；
- 网页公司雷达双栏内容；
- 21 源监控 API 和原 7 个指定来源顺序保持稳定。

全量 226 项测试，其中 22 项 Playwright；核心语句与分支覆盖率 100%。

## 8. 下一步

优先为当前能直接读取职位列表的专注型来源实现解析器。候选顺序：Fireworks AI、Baseten、LlamaIndex、Pinecone。每次只接一个来源，并先保存 Fixture、验证地点与岗位链接，再加入实时 Feed。

## 9. 行为准则

- 不用品牌知名度替代岗位价值；
- 不用“独角兽”标签替代可验证的方向和职位事实；
- 公司目录与监控注册表必须是同一事实源；
- 大厂和探索池必须有显式配额或混排，不能只按数量排序；
- 官方 Careers 页面存在不代表当前有适合用户的岗位；
- 地区、远程和签证必须在岗位级再次核验。
