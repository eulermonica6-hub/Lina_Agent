# 迭代 042：浏览器文件 Agent

> 日期：2026-09-28
> 阶段：Phase 3A.6 浏览器运行入口
> 状态：文件上传、结果展示与历史刷新已完成

## 1. 目标

把已有 `POST /agent/runs` 接入工作台。用户可在浏览器选择简历和 Markdown 岗位目录，显式启用自动决策信号或 LLM 计划，并在同一页面查看 Top 匹配、技能缺口和更新后的运行历史。

## 2. 交互与契约

- 简历接受 TXT、Markdown 和 DOCX；岗位目录接受 Markdown；
- 浏览器读取文件字节并 Base64 编码，提交 `{filename, content}`，不暴露客户端路径；
- Top-K 限制为 1 到 50；自动信号和 LLM 默认关闭；
- 自动信号开启后才启用并提交到岗天数、连续月份与六类方向偏好；
- `0.0` 是有效方向偏好，空输入才省略；
- 成功后展示状态、匹配分数、聚合 gap 和 warning，并调用同一历史加载函数；
- API 失败后恢复提交按钮并显示服务端 detail。

## 3. 隐私边界

原始文件内容只发送到本地 Lina API。运行历史继续使用脱敏 Snapshot，不保存 Base64、正文、offset 或私密文件名，也不在历史区重新展示上传文件名。页面不接受服务端文件路径。

## 4. 状态与竞态

文件 Agent 使用独立 revision。请求期间若用户更换文件或参数，旧成功/失败响应不能渲染为当前结果；按钮仍会恢复。手动刷新和运行成功后的自动刷新复用 `loadHistory()`，历史与 Diff 保持各自 revision。

## 5. 响应式与可访问性

桌面端文件区三列、确认区四列、结果区两列；移动端统一转为单列。自动信号开启时确认区自动展开，关闭时禁用并清空确认字段。实测桌面和移动视口均无横向溢出。

## 6. 验证

新增 5 个 Playwright 场景：

1. TXT/Markdown 上传、Base64、确认参数、结果渲染和历史自动刷新；
2. 自动信号开关联动确认字段；
3. DOCX 字节、LLM opt-in，以及关闭自动信号时省略确认；
4. API 失败后的错误展示和按钮恢复。
5. 提交后更换文件使旧 Run 响应失效。

完整 Web 套件共 17 项通过，桌面与移动截图验收通过。

## 7. 知识与行为准则

- 浏览器文件输入应上传内容，不应要求或泄露服务端路径。
- 高影响自动信号和付费 LLM 都必须显式 opt-in。
- 禁用字段不等于安全省略，构造 payload 时仍需按开关建立白名单。
- 自动刷新必须调用共享加载函数，不能模拟点击制造第二套状态机。
- 文件读取也属于异步请求的一部分，revision 应覆盖读取、提交和渲染全链路。
- 历史持久化成功由服务端负责，前端只消费响应并刷新脱敏投影。
