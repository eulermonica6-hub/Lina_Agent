# 迭代 006：推送前审查与正确性加固

> 日期：2026-08-23
> 阶段：Phase 2 质量加固
> 状态：已完成

## 1. 用户问题

在首次提交完整 MVP 前，对包含未跟踪文件的整个工作树进行审查，修复可能产生错误求职结论、错误评测结论或前端状态错位的问题，再执行质量门禁并推送。

## 2. 审查方法

普通 `git diff` 不包含未跟踪文件，因此本轮先结合 `git status`、未跟踪文件清单、敏感信息扫描和独立代码审查覆盖完整工作树。审查发现四项阻断问题：

1. “硕士优先”“3 年经验者优先”会被提升为硬门槛；
2. 地点分隔器按单个“和”切割，导致“和田”变成“田”；
3. 匹配请求等待期间修改表单，旧响应仍会覆盖新状态；
4. 空评测集会因零分母规则得到全项满分。

修复后的独立复审继续发现并关闭边界：带标点和前后置“优先考虑”语气、偏好毕业年份、无法可靠拆分的“北京和上海”、包含连词字样的“新疆和田”，以及保存、提取和匹配失败响应的新鲜度与状态提示。

## 3. 测试驱动修复

### 3.1 偏好不是硬约束

先加入“偏好在前、真实门槛在后”的回归案例。旧实现返回硕士和 3 年经验，测试失败。修复后，解析器遍历匹配项，过滤紧跟“优先/者优先”的候选，只保留明确硬条件，因此学历取本科，经验保持为空。

该方案刻意保持高精度：目前只识别紧邻偏好后缀，不尝试推断更复杂的自然语言语气。复杂表达继续由人工确认，未来再由结构化 LLM 抽取和 Verifier 补充。

### 3.2 地名不能按单字符连词切割

旧分隔器把“或”“和”放在字符类中，意味着每个单字都会触发切割。“工作地点：和田”因此只剩“田”。修复后只按 `、`、`,`、`，`、`/` 等明确标点分隔。自然语言并列地点暂不冒险解析。

### 3.3 旧异步响应不能写入新状态

匹配开始时保存候选人与岗位 ID。响应返回后，只有当前状态仍持有同一对 ID 才渲染结果或错误。用户编辑或重置会废弃相应 ID，所以旧响应被忽略。保存和提取请求使用统一状态修订号校验，`finally` 只恢复控件，不写入过期业务结果。

真实浏览器验收使用延迟 `/matches` 响应：请求发出后修改毕业年份，再释放旧响应。页面最终仍为“等待分析”，按钮禁用，并提示重新保存。

### 3.4 空数据不是满分

`evaluate_job_parser` 现在拒绝空案例集并抛出 `ValueError`。评测系统缺少样本时应失败，而不是生成看似成功的指标。

## 4. 核心知识点

- 业务文本中的“优先”与“要求”具有不同决策等级，错误提升偏好会制造假阴性；
- 正则字符类按单字符匹配，不能用来表达多字符自然语言连接词；
- 前端异步响应必须验证请求身份，按钮状态应由当前业务状态派生；
- 指标的零分母语义必须按场景定义，数据集为空属于输入错误；
- pre-commit review 必须显式覆盖 untracked 文件，否则可能漏掉主体实现。

## 5. 开发心得

1. 对求职筛选系统，误设硬门槛比漏掉预填更危险，应优先保证 Precision。
2. 正则越宽松，越需要地名、公司名等词内反例。
3. 前端状态清空不等于请求失效，网络响应仍可能晚到。
4. 评测工具也属于生产代码，必须为无数据和损坏数据设计失败语义。
5. 独立审查最有价值的输出是可复现反例，而不是笼统风格建议。

## 7. 遗留风险

- “加分项”“可放宽”等更多偏好语气尚未结构化分类；
- “上海或杭州”一类自然语言地点并列不会自动拆分；
- 当前浏览器竞态场景是手工 Playwright 验收，尚未进入自动化测试套件；
- 规则解析仍需扩大匿名真实 JD 反例集。
- 发布包静态资源由 setuptools package-data 声明，但 wheel 内容仍待工具链恢复后验证。

## 8. 面试素材

### 30 秒表达

> 在首次推送 MVP 前，我审查了包含未跟踪文件的完整工作树，找到了四类会制造错误结论的问题：偏好条件被当成硬门槛、地名“和田”被连词规则切坏、旧匹配响应覆盖新表单状态，以及空评测集得到满分。我先写反例复现，再做最小修复，并用延迟 API 响应做真实浏览器验收。这一轮让我把求职产品最重要的两个不变量固定下来：只有明确要求才能淘汰候选人，异步结果只能写回发起它的那一版状态。

### 高频追问

**为什么不直接让正则支持所有偏好表达？**
当前产品的硬条件结果会影响是否投递，误提取成本高。第一版只处理可明确判定的紧邻后缀，其余表达保留人工确认，避免为了召回率牺牲精度。

**为什么不只在重置时禁用按钮？**
按钮状态不能阻止已经在途的响应。必须在响应写入 UI 前比较请求发起时与当前的实体身份，才能保证状态一致性。
