# 迭代 010：文档治理与数据标注规范

> 日期：2026-08-24
> 类型：工程治理、隐私与评测准备
> 状态：文档治理与简历匿名化已完成，JD 采集等待用户提供可访问来源

## 1. 用户问题

用户要求 README 链接所有重要文档，版本更新时统一 Review，并将文档管理沉淀进知识库；同时希望从 Boss 直聘准备 10 条 AI JD、匿名化既有简历，并理解人工标注的必要性和操作方式。

## 2. 实现与决策

- 新增文档治理清单，明确重要文档职责、事实来源和发布 Review 步骤；
- 新增 README 文档链接契约，重要文件缺失或未链接时测试失败；
- 新增数据匿名化与标注指南，定义 AI 初标、人工确认和 Gold Label；
- 明确完整第三方 JD 与原始简历只进入 `data/private/`，公开仓库只保存必要、合规的短片段或结构化标签；
- 文档治理属于工程增量，不新增用户功能，因此版本保持 `0.1.0`。

## 3. 失败与边界

首次文档契约测试因 `docs/DOCUMENTATION_GOVERNANCE.md` 不存在而失败，证明测试能够捕获缺失文档。

Boss 直聘公开搜索页只返回动态加载壳，集成浏览器随后被站点关闭；通过搜索引擎访问又触发验证码。没有绕过登录、验证码或反爬限制。后续需要用户共享已登录页面，或正常浏览后导出 10 条 JD 文本。

提交前检查发现工作区根目录出现了原始简历 PDF，文件名包含真实姓名。文件未加入 Git，并立即移动到 `data/private/resume_raw/` 后改为中性文件名。macOS PDFKit 成功离线提取文本；现有公开匿名 Fixture 的核心事实得到原文支持，另在 `data/private/resume_anonymized/` 生成了更完整的匿名副本。联系方式与 URL 扫描未发现残留。

## 4. 标注知识

标注是被测系统之外的期望答案。当前 JD 标签包括毕业年份、最低学历、最低经验、地点和支持这些值的最小原文片段。

AI 可以完成匿名化、候选标签、证据定位和格式校验；人工负责确认“硬门槛还是偏好”等高影响语义。AI 初标加人工复核比完全手工更高效，也比模型自评更可靠。

## 5. 后续验收

1. 用户提供可访问的 10 条 Boss JD；
2. AI 生成私有匿名副本与初标；
3. 用户按歧义清单完成 30-45 分钟复核；
4. AI 生成评测 JSON，验证证据子串与 Schema；
5. 运行基线并记录真实集指标；
6. 隐私和内容授权检查通过后，再决定可进入 Git 的最小数据。

## 6. 面试表达

> 我把文档一致性和数据标注都做成工程契约：README 必须链接所有重要文档，发布时按事实来源统一 Review；真实 JD 先在私有目录匿名化，由 AI 初标硬条件和证据，再由人工确认高影响歧义，形成独立 Gold Label。这样模型不会既生成答案又给自己打分，指标也能用于后续规则、Prompt 和模型回归。
