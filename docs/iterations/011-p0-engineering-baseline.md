# 迭代 011：P0 工程基线与浏览器竞态自动化

> 日期：2026-08-26
> 类型：跨平台可靠性、依赖可复现、浏览器回归
> 状态：已完成

## 1. 用户目标

在继续核心 Agent 能力前先偿还四项工程基线：

1. 修复 Windows UTF-8 测试问题；
2. 增加 Windows CI；
3. 固化依赖锁文件；
4. 将前端异步状态的手工 Playwright 验收转为正式测试。

本轮不增加职业决策功能，不接入 LLM，不改变 API 与领域语义。

## 2. 修改前证据

Windows 中文区域设置下直接运行全量测试时，5 个测试因 JSON Fixture 使用系统默认 GBK 解码 UTF-8 文件而失败，覆盖率随之降为 94.26%。临时启用 Python UTF-8 模式后，原有 38 个测试与 100% 覆盖率通过，证明失败属于文件读取边界，而不是业务逻辑。

前端已经使用修订号和实体 ID 防止旧异步响应覆盖新状态，但延迟响应场景只存在于手工验收记录中。CI 仅运行 Ubuntu，依赖也只有允许版本范围，没有锁文件。

## 3. 操作与作用

### 3.1 显式 UTF-8 读取

在两处 JSON Fixture 读取中增加 `encoding="utf-8"`。编码是文件格式契约，不应由操作系统区域设置决定。没有使用全局 `PYTHONUTF8=1` 掩盖遗漏，Windows CI 将直接保护这些读取边界。

### 3.2 建立真实浏览器测试服务器

测试 Session 在空闲端口启动真实 FastAPI 应用和静态资源，结束时显式停止 Uvicorn 线程。这样页面、HTML 和 `app.js` 来自实际应用装配，而不是复制到测试中的 HTML 片段。

### 3.3 在浏览器边界控制响应时机

Playwright 在页面脚本运行前安装可延迟的 `fetch` 替身。测试先让请求进入等待状态，再修改表单，最后释放旧响应。该设计不依赖真实网络延迟，能够确定性复现竞态，同时继续由已有 API 测试验证后端 HTTP 契约。

正式矩阵覆盖：

| 在途请求 | 旧成功响应 | 旧失败响应 | 必须保持的新状态 |
| --- | --- | --- | --- |
| 候选人保存 | 已覆盖 | 已覆盖 | 画像未保存、匹配禁用 |
| 岗位保存 | 已覆盖 | 已覆盖 | 岗位未保存、匹配禁用 |
| JD 抽取 | 已覆盖 | 已覆盖 | 不显示旧证据、不回填旧约束 |
| 岗位匹配 | 已覆盖 | 已覆盖 | 结果保持等待分析、要求重新保存 |

每个浏览器测试还会收集未处理的 `pageerror`，避免断言通过但页面脚本已经报错。

### 3.4 固化依赖

开发依赖加入 `pytest-playwright`，通过 `uv lock` 生成跨平台 `uv.lock`。`pyproject.toml` 继续表达允许范围，锁文件保存精确解析结果。CI 使用 `uv lock --check` 和 `uv sync --locked`，锁文件缺失或落后于项目元数据时必须失败。

浏览器二进制不写入 Python 锁文件；由锁定版本的 Playwright CLI 安装对应 Chromium revision。

### 3.5 Linux/Windows CI 矩阵

GitHub Actions 从单一 Ubuntu job 扩展为 `ubuntu-latest` 与 `windows-latest`。两边运行相同的 Ruff、Pyright、pytest 和覆盖率门禁。Linux 额外安装浏览器系统依赖，Windows 直接安装 Chromium。浏览器测试失败时上传 `test-results/` Trace。

## 4. 实施中发现的问题

### 4.1 `pytestmark` 容器类型

第一次收集浏览器测试时使用元组保存模块标记，pytest 8.4 将整个元组视为非法标记对象。改为标记列表后，8 个参数化场景正常收集。

### 4.2 严格类型检查与测试数据

包含空列表的嵌套响应常量会被 Pyright 推断出 `Unknown`。为浏览器响应 Fixture 显式标注 `dict[str, Any]` 后，strict 模式重新变为 0 错误。

### 4.3 锁文件跨平台，虚拟环境不跨平台

工作区原有 `.venv` 是 Linux/WSL 格式，不能作为 Windows 解释器环境。验证时从锁文件同步到独立 Windows 环境。后续在 Windows 与 WSL 间切换时必须使用不同虚拟环境，不能共享 `.venv`。

### 4.4 保存存在两个独立处理器

最初只自动化候选人保存。最终 Review 发现岗位保存是另一套独立事件处理器，因此补充岗位保存的成功与失败竞态测试，避免用一个路径代表两个实现。

## 6. 工程知识总结

1. 文件编码要在读取边界显式声明，不能依赖开发机默认值。
2. 锁文件固定依赖解析，虚拟环境仍然是操作系统相关的可丢弃产物。
3. 异步 UI 正确性的核心是请求身份，而不是按钮是否暂时禁用。
4. 竞态测试必须主动控制时序，依赖 `sleep` 会形成慢且不稳定的测试。
5. API 测试与浏览器测试职责不同：前者验证后端契约，后者验证页面状态机。
6. CI 失败应留下 Trace 等可诊断证据，而不只是退出码。
7. 只有分别覆盖独立事件处理器，才能声称对应业务路径受到回归保护。
