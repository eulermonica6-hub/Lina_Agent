# 迭代 063：已投递岗位标记与推荐排除

> 日期：2026-10-01
> 版本：0.2.45
> 状态：投递标记、撤销、持久化与推荐过滤已完成

## 1. 用户确认

- 已投递标记允许撤销，避免误操作永久隐藏岗位；
- 已投递岗位从所有默认推荐场景排除，包括首页和自然语言默认比较；
- 手动搜索仍可查到已投递岗位，便于回看并执行撤销。

## 2. 实现

- 新增独立 `JobApplicationRecord`，使用 `source_id + external_id` 作为稳定投递键；
- SQLite schema 升级到 v6，持久化公司、标题、官方 URL 和投递时间；
- 新增投递列表、标记和撤销 API；
- 推荐服务在 live 过滤后排除已投递键，搜索服务不排除；
- 首页岗位卡新增“标记已投递”；标记后刷新推荐并立即移除该岗位；
- 手动搜索中的已投递岗位显示“撤销已投递”；撤销后恢复推荐资格；
- 自然语言默认比较复用推荐服务，因此不会再次选择已投递岗位。

## 3. 对话实现说明

当前自然语言对话不调用 LLM，不需要 API key。它使用确定性别名和意图规则，将输入转换为类型化搜索、Inbox 或比较请求，再调用 Python 应用服务。这样默认测试不访问模型，结果保留官方来源和状态。

限制是当前只支持已定义意图和单轮输入；复杂开放式表达、上下文承接和生成式解释将在多轮会话完成后，以显式可选模型增强评估，不会默认偷偷调用外部模型。

## 4. 验收

- 已投递岗位从推荐中消失，但仍存在于手动搜索；
- 撤销后恢复推荐资格；
- API 列出投递记录，未知撤销返回 404；
- SQLite Repository 重启后投递记录仍存在；
- 推荐卡标记后即时消失；手动搜索可撤销；
- 推荐、搜索、API 和浏览器测试均覆盖该闭环。

## 5. 下一步

下一里程碑不变：持久化多轮会话状态、待补字段和最小工具摘要，使主动追问后的回答能承接上一轮条件。
