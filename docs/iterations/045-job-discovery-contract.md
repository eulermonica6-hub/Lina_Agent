# 迭代 045：岗位发现契约与手动搜索

> 日期：2026-09-28
> 阶段：主动求职产品的来源架构
> 状态：统一领域契约、快照适配器和手动搜索已完成

## 1. 目标

把 0.2.26 中直接写在 API 路由里的岗位快照迁移为可替换来源架构，并让用户在首页按关键词、公司和地点手动搜索当前数据源。

## 2. 领域契约

新增：

- `JobLead`：来源记录、跨来源去重键、公司、标题、地点、方向、URL、抓取时间、核验状态和摘要；
- `JobSearchRequest`：关键词、公司、地点与全局结果上限；
- `JobSourceStatus`：成功、部分成功、限流、禁止访问、结构变化和失败；
- `JobSourceResult`：来源健康、抓取时间、原始 leads 和错误码；
- `JobDiscoveryResult`：所有来源结果与全局去重后的 leads。

`lead_id` 表示来源内记录身份，`deduplication_key` 表示跨来源岗位身份。两者不能混用，否则同一岗位来自两个渠道时无法合并。

## 3. 应用与基础设施

`JobSourceAdapter` Protocol 只声明 `source_id` 和异步 `search()`。`JobDiscoveryService` 负责：

1. 调用所有来源；
2. 保留每个来源的成功或失败状态；
3. 按 `deduplication_key` 保留首个岗位；
4. 在去重后应用全局结果上限。

`VerifiedSnapshotJobSource` 是首个适配器，只读取 2026-09-14 历史核验数据，不访问公网。它实现不区分大小写的关键词、公司和地点过滤，并将“成功但没有匹配”与来源失败分离。

## 4. API 与网页

新增 `POST /opportunities/search`：

```json
{
  "query": "agent",
  "companies": ["MiniMax"],
  "locations": ["上海"],
  "max_results": 50
}
```

响应同时包含 `sources` 和去重后的 `leads`。原有 `GET /opportunities` 也改为调用同一个 `JobDiscoveryService`，不再拥有平行硬编码数据。

首页新增关键词、公司和地点搜索表单。搜索结果继续使用岗位卡展示来源时间，并成为只上传简历初筛的当前岗位集合。

## 5. 验证

新增和扩展测试覆盖：

- 不同 lead ID、相同去重键的跨来源合并；
- 全局 limit 在去重后执行；
- 关键词、公司和地点过滤；
- 成功空结果不标记为失败；
- API 搜索参数、来源健康与结果；
- 浏览器搜索请求、岗位卡更新和来源健康展示。

全量 210 项测试通过，其中 21 项 Playwright；语句和分支覆盖率均为 100%。

## 6. 下一步

在不修改领域和 API 契约的前提下，实现首个实时官方来源适配器：

1. 选择无需登录、条款允许且接口稳定的官方招聘来源；
2. 保存 HTML/JSON Fixture，默认测试不访问公网；
3. 独立真实探针记录响应时间、状态和字段完整度；
4. 映射为 `JobLead`，并保留来源失败而不是伪造空结果；
5. 与快照来源并行运行，验证跨来源去重。

## 7. 行为准则

- 来源健康是结果的一部分，不是日志细节；
- 空结果和失败必须使用不同状态；
- 去重身份不得依赖来源 ID；
- API 只依赖应用服务，不持有来源数据；
- Fixture 测试与真实网络探针必须分离。
