# 迭代 029：多冻结 Gold 套件基线

> 日期：2026-09-24
> 阶段：Phase 2B.8 多数据集稳定性评测
> 状态：评测框架完成；新增真实 Gold 待补完整 JD 与人工排序

## 1. 问题

单个 5 岗 Gold 上的方向 MAE、Top-1 和 Pairwise 均为 `1.0`，但这些指标不能说明跨公司、跨岗位族或跨时间稳定。直接把职位族摘要加入原数据集会缺失完整技能、硬条件和引用证据，也会替用户编造排序。

## 2. 实现

- 新增 `CareerMatchingGoldSuite`，用版本化 manifest 引用多个独立冻结数据集。
- 新增 `AutomaticDecisionSuiteReport`，保留每个数据集报告并汇总：
  - 数据集数与总岗位数；
  - JD 实际命中的方向族及 taxonomy 覆盖率；
  - direction MAE 的宏平均与最大值；
  - Top-1、Pairwise 的宏平均；
  - 最差数据集 Pairwise。
- CLI 新增 `--auto-signal-suite`，manifest 内路径相对 manifest 所在目录解析。
- 私有目录建立 suite manifest、聚合报告和 5 项扩展标注 backlog。

## 3. 首轮基线

当前 suite 仍只有原冻结集：

| 指标 | 结果 |
| --- | ---: |
| 数据集数 | `1` |
| 岗位数 | `5` |
| 方向族覆盖率 | `1.0` |
| macro direction MAE | `0.0` |
| macro Top-1 | `1.0` |
| macro Pairwise | `1.0` |
| minimum Pairwise | `1.0` |

五类 taxonomy 都有岗位命中，但样本仍来自同一批次，因此覆盖完整不等于泛化充分。

## 4. 失败与修复

1. 首次测试使用嵌套临时目录但未创建目录，导致 `FileNotFoundError`；修复夹具后继续验证产品逻辑。
2. 首次实现将 suite 函数插入单数据集函数中部，使原函数隐式返回 `None`。根因是补丁锚点选择了前一个 `sorted()` 结束位置，而不是函数最终 `return`。修复后将聚合函数移到完整函数边界之外。
3. 初版“方向覆盖率”按用户偏好字段计数，会因每个数据集复用同一用户配置而虚高。修正为统计 JD 实际命中的 `DirectionEvidenceItem.name`。

## 5. 知识与行为准则

- taxonomy coverage 衡量类别是否出现，dataset count 与 job count 衡量样本规模，三者不能互相替代。
- 多数据集评测同时报告宏平均和最差集；只报总体平均会掩盖单一岗位族退化。
- 每个 Gold 集应独立冻结简历、JD、标注策略、排序与 ties；suite 只聚合，不重写单集事实。
- 职位标题或职位族摘要不能替代完整 JD，不进入技能引用 Gold。
- 未经用户确认的相对偏好只能进入 backlog，不能写入 `gold_ranking`。
- 在长函数附近插入新函数时，必须用完整函数边界作为补丁锚点，并立即运行原函数的既有测试。

## 6. 私有扩展 backlog

已登记五类候选：Agent 研发、Agent 能力研究、AI 社区产品、大模型算法评测和 AI Tools 软件工程。每项记录缺失的完整官方 JD、投入事实、技能证据或用户排序；满足全部条件后才晋升为第二个冻结集。

## 7. 下一步

获取候选岗位的完整官方 JD 并匿名化，完成逐项技能/hard 标签；随后只向用户确认无法由文档推出的排序与 ties，生成第二个独立 Gold 数据集并复跑 suite。

## 8. 面试表达

当单个 5 岗数据集达到满分后，我没有直接宣布排序可泛化，而是增加版本化多 Gold 套件，同时报告方向族覆盖、宏平均和最差数据集指标。盘点发现候选池只有摘要，因此我把它们留在私有标注 backlog，而没有伪造引用或人工排序。这让“类别覆盖完整”和“样本充分”成为两个可观测、不可混淆的结论。
