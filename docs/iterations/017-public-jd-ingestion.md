# 迭代 017：公开真实 JD 摄取与匿名化

> 日期：2026-09-03
> 阶段：Phase 2B 真实数据基线
> 状态：匿名候选集已完成；经人工范围复核，全部为正式岗，仅保留为负例候选

## 1. 用户问题

Boss 直聘触发动态加载和访问验证，无法在不绕过站点限制的前提下稳定获取 JD。本次目标是改用可公开读取的官方招聘来源，收集 10 条中国 AI 相关岗位，并建立可复跑的原始快照和匿名副本。后续人工复核补充了“上海、2028 届、实习”的目标约束，因此本批数据不再作为目标岗位候选。

## 2. 来源与边界

- 来源：Amazon Jobs 官方公开搜索接口；
- 查询：`base_query=AI`、`country=CHN`；
- 范围：8 条上海岗位、2 条北京岗位；
- 岗位族：AI Agent 工程、Applied Science、Data Science、技术产品、解决方案架构和软件开发；
- 不绕过登录、验证码、反自动化或 406 响应；
- 原始与匿名完整正文均只保存于 `data/private/`，不提交 Git。

匿名副本删除公司与品牌词、URL、申请入口、内部 UUID 和官方职位 ID；保留岗位标题语义、城市、职责、学历、经验、毕业年份、技能和发布日期。匿名层使用稳定 `case_id` 与同序原始快照对应。

## 3. 实现

可复跑脚本：

```bash
uv run --locked python scripts/ingest_amazon_ai_jobs.py
```

输出：

- `data/private/jd_raw/amazon_china_ai.json`：来源、查询条件、采集时间与完整官方对象；
- `data/private/jd_anonymized/china_ai_jobs.json`：10 条去公司化岗位正文。

脚本固定目标职位 ID。若岗位从中国搜索结果中消失，会明确失败，不会静默用其他岗位替换，从而避免数据集内容随搜索排序漂移。

## 4. 实际失败与根因

### 地区搜索参数失效

`loc_query=China` 只是搜索框文本，后端请求中的 `location` 仍为 `null`，结果包含全球岗位。改用 `country=CHN` 后，返回项的 `country_code` 均为 `CHN`；`city=Shanghai` 也可独立生效。

### Python HTTPS 证书失败

`urllib.request` 在本机 Python 3.12 环境报 `CERTIFICATE_VERIFY_FAILED`，而系统 `curl` 使用系统信任链可正常访问。脚本改为调用 `curl -fsSL` 并检查退出码，没有通过禁用 TLS 验证规避问题。

### 中英混排导致品牌漏脱敏

首版品牌正则使用 `\b`。在 Unicode 规则下，汉字和英文字母都属于单词字符，`利用AWS` 前不存在单词边界，导致 `AWS` 残留。移除边界后，中英文相邻场景通过扫描。

### 重复私有简历

旧目录中含真实姓名的 PDF 与 `resume_raw/original-resume.pdf` 的 SHA-256 完全一致。删除重复副本和空目录，只保留规范化文件名。

## 6. 数据状态与下一步

当前数据是 AI 完成来源筛选和匿名化后的正式岗负例候选，不是目标实习 Gold Label。保留它们可用于验证硬条件过滤是否拒绝非实习、错误毕业年份和高经验门槛，但不得与实习正例混合统计。目标正例应重新从官方实习项目收集，并逐条确认：

1. 是否明确接受 2028 届；
2. 是否位于上海、每周可实习 5 天且至少持续 3 个月；
3. 学历和经验表达是硬要求、偏好、歧义还是未声明；
4. 哪些最小原文片段可作为字段证据。

确认后再生成真实评测 JSON，并运行当前解析器基线。不能根据解析器输出反向修改人工标签。

## 7. 面试素材

> 招聘网站访问受限时，我没有绕过验证，而是切换到官方公开职位接口。实现中先验证地区参数，发现搜索框的 `loc_query` 并不产生后端地点过滤，最终用 `country=CHN` 并检查每条国家代码。原始快照和匿名副本分层保存，匿名层去除公司、URL 和职位 ID，同时保留影响筛选的学历、经验与城市。过程中还定位了 Unicode 单词边界导致中文紧邻 `AWS` 漏脱敏的问题。最终 10 条真实 JD 可重复生成，但在人工确认前明确只称为匿名候选集，不称为 Gold Label。
