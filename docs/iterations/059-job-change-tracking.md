# 迭代 059：NVIDIA 岗位批次与变化检测

> 日期：2026-09-30
> 版本：0.2.41
> 状态：完整详情指纹、跨批次状态和四类变化事件已完成

## 1. 决策确认

用户确认：

- 抓取范围覆盖 NVIDIA Workday 查询返回的全部上海岗位，而不只限 AI 或早期岗位；
- SQLite 保存规范化岗位正文与 SHA-256 指纹，不保存 HTML、Cookie 或完整 HTTP 响应；
- 首次抓取静默建立基线，不为全部已有岗位生成 `new` 事件。

## 2. 实现

- NVIDIA 列表解析器进一步读取每个职位的官方详情 JSON；
- 使用标准 `HTMLParser` 将职责和要求规范化为纯文本；
- 指纹覆盖标题、地点、岗位类型、方向、规范化正文、开始日期和工时类型；
- 新增抓取批次、岗位最新状态和变化事件领域模型；
- 新增确定性变化服务，生成 `new / updated / closed / reopened`；
- SQLite schema 升级到 v4，单事务保存批次、状态和事件；
- 每周监控只对 `success` 的 NVIDIA 完整批次执行比较，`partial/failed` 不触发关闭；
- 周报 JSON artifact 包含本轮批次与变化事件，供后续 Inbox 消费。

## 3. 多地点边界

Workday 对 `Shanghai` 查询可能返回 `2 Locations`，但详情 JSON 只给主地点。对于该查询返回且标记多地点的北京主地点职位，Lina 保存为 `北京 + 上海`；普通非上海单地点职位不进入批次。

## 4. 验收

离线测试覆盖：

- 首批静默建立基线；
- 相同批次重复执行不产生事件；
- 新增、字段/正文更新、关闭和重开；
- partial 批次不关闭岗位；
- SQLite Repository 重启后继续比较；
- 详情 HTML 规范化、稳定指纹、多地点和完整分页。

真实验收：

- NVIDIA 完整抓取状态为 `success`；
- 确认 40 条包含上海的岗位，40/40 具有规范化正文和指纹；
- 首批写入临时 SQLite，0 事件；
- Repository 重启后恢复 40 个岗位状态；
- 第二次实时抓取仍为 40 条且 0 事件。
