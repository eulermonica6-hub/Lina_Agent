# 迭代 058：持续项目记忆与进度闭环

> 日期：2026-09-30
> 版本：0.2.40
> 状态：每次任务的知识沉淀、总览审阅、进度报告和下一步提示已制度化

## 1. 问题

仓库已经有 README、知识库、Coding Plan 和迭代日志，但没有 always-on 规则要求每次任务同步这些事实，也缺少一个只描述“当前状态”的进度文档。长期迭代后容易出现代码完成、文档滞后，或者下一会话需要重新梳理上下文。

## 2. 实现

- 新增 `.github/copilot-instructions.md`，作为 VS Code/Copilot 的项目级常驻工作规范；
- 明确每次任务开始前读取项目总览、当前进度、Coding Plan 和相关知识；
- 明确每次任务结束执行四项沉淀：知识、项目总览、进度报告和下一步；
- 新增 `docs/PROJECT_STATUS.md`，只保存当前版本、最近完成、验证、边界、风险和下一里程碑；
- README 继续作为项目总览，`KNOWLEDGE_BASE.md` 和迭代日志保存历史知识，`CODING_PLAN.md` 保存下一步依赖顺序；
- 增加文档测试，防止四项规则或入口被误删。

## 3. 文档职责

| 文档 | 职责 | 更新频率 |
| --- | --- | --- |
| `README.md` | 项目总览、用户能力和主要入口 | 能力或边界变化时 |
| `docs/PROJECT_STATUS.md` | 当前进度、验证、风险和阻塞 | 每次任务 |
| `docs/CODING_PLAN.md` | 下一里程碑和长期依赖顺序 | 每次任务审阅 |
| `docs/KNOWLEDGE_BASE.md` | 可验收迭代历史索引 | 每个可验收增量 |
| `docs/iterations/NNN-*.md` | 决策、实现、失败和验证细节 | 每个可验收增量 |

历史迭代发布后冻结，不用新事实改写旧版本。

## 4. 验收

- 项目级 Copilot 指令文件存在并包含四项沉淀；
- 当前进度报告存在并包含版本、最近完成、验证、边界、风险和下一里程碑；
- README 提供工作规范、项目状态、知识库和 Coding Plan 的直接入口；
- 文档契约测试通过；
- 本次任务按新规范完成首次完整沉淀。
