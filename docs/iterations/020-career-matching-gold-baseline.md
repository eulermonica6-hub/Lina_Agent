# 迭代 020：技能证据与 Top-K Gold 基线

> 日期：2026-09-14
> 阶段：Phase 2B 真实数据评测
> 状态：完成首轮基线；排序特征不足已量化

## 1. 用户问题

前一轮已经筛出 5 条优先实习，但只有资格摘要，无法复现技能抽取、引用和排序结果。本轮保存官方正文快照，建立匿名人工 Gold，并回答两个问题：当前证据链是否可信，以及仅调整技能权重能否得到人工期望的 Top-K。

## 2. 数据边界

- `data/private/jd_raw/` 保存 5 份带公司、职位 ID、来源 URL 和快照日期的官方正文。
- `data/private/jd_anonymized/shanghai_ai_intern_gold.md` 保存去公司名、URL 和职位 ID 的统一目录。
- `data/private/evaluation/career_matching_gold_v1.json` 保存三类岗位技能、候选人直接支持技能和人工排名。
- `data/private/evaluation/career_matching_report_v1.json` 保存完整运行结果。
- 所有文件继续由 `data/private/` 总规则忽略，不进入 Git。

## 3. 实现

`MatchWeights` 将原先硬编码的 `0.7 / 0.2 / 0.1` 提取为类型化配置，默认行为不变。新增评测器同时计算岗位技能、候选人匹配、引用和排序指标，并搜索 20 组总和为 1、required 权重不低于 0.5 的可解释组合。

首轮发现 `LLMs` 与 `HTTP / API` 没有进入现有词表，且一条同时包含硬要求与“加分”的复合句会整句误归为 preferred。修复方式是增加有明确语义的别名，并在匿名评测目录中拆分条款；原始官方快照不改写。

人工复核还发现初版 Gold 把 Git、Machine Learning 和 Prompt Engineering 等合理推断当成了简历直接证据。由于匿名简历没有对应原文，这些标签被移除。Gold 的职责是描述证据，而不是替模型补齐事实。

## 4. 结果与判断

岗位技能、候选人匹配、引用有效率和引用支持率均达到 `1.000`。默认排序 Pairwise Accuracy 仅 `0.300`，Top-1 为 `0.000`；最佳网格权重只提升到 `0.400`，Top-1 不变。

因此本轮不把网格最优权重升级为默认值。人工排序包含硬条件风险和职业方向偏好，当前评分器只计算技能覆盖。这个失败不是继续微调权重可以解决的，应先统一硬条件链与文件证据链，并显式建模方向适配度。

> 我先为真实岗位建立匿名 Gold Set，并把技能抽取、候选人匹配、引用有效性和 Top-K 排序分开评测。抽取和引用达到满分，但排序 Pairwise Accuracy 只有 0.3；20 组权重搜索也只能提升到 0.4。由此证明问题不在参数，而在缺少硬条件和方向适配特征，因此拒绝在 5 条样本上过拟合权重，并把下一步转向双链统一和消融评测。

## 8. 学习笔记

### 8.1 Gold 描述证据，不描述“常识上应该会什么”

第一版标注把 Git、Machine Learning 和 Prompt Engineering 当成候选人已支持技能，因为项目经历看起来足以推断这些能力。但匿名简历没有对应原文，继续保留会让评测奖励无证据推断。Gold 必须区分“文本明确支持”“合理推断”和“待人工确认”；当前确定性基线只消费第一类。

### 8.2 引用有效不等于引用支持

字符偏移能还原原文，只证明引用没有错位；引用文本确实是目标技能的别名，才证明它支持结论。因此评测同时保留 citation validity 和 citation support，避免系统精准引用一段无关文本仍获得满分。

### 8.3 排序失败不一定是权重失败

技能抽取和匹配达到满分后，Top-K 仍明显偏离人工排序，说明评分输入缺少决定性变量。岗位 4 的技能要求较少且命中率高，却有一年实习承诺和方向偏差；覆盖率模型看不到这些风险。此时继续搜索权重是在错误特征空间里优化。

### 8.4 小数据校准要允许“拒绝发布参数”

20 组权重中最优 Pairwise Accuracy 只从 `0.3` 提升到 `0.4`，Top-1 仍为 `0`。这不足以替换默认值。一次合格的校准可以得出“不改参数”的结论，并把失败转化为下一轮特征工程的验收标准。

### 8.5 原始快照与评测文本职责不同

原始快照忠实保存官方措辞；匿名评测目录可以拆分“必选要求 + 加分条件”的复合句，以表达人工确认后的结构语义。两者不能互相覆盖：前者用于审计，后者用于稳定评测。
